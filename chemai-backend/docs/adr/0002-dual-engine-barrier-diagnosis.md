# 障碍诊断采用「规则引擎 + LLM」双引擎融合（LLM 主判）

障碍诊断（Barrier Type + Misconception Category）需要同时满足准确性与成本/可解释性。规则引擎（关键词匹配）低成本、可离线、结果可解释，但覆盖不了语义复杂场景；LLM 语义分析准确，但昂贵且输出不稳定。因此采用三引擎三段式：规则引擎 → LLM 深度诊断 → 置信度融合引擎。分类以 LLM 为主判，规则引擎承担「上下文喂入 / 兜底 / 矛盾校验」三角色；置信度融合引擎合成最终置信度。

**状态**：accepted

## 备选方案

- **规则 + LLM 平权投票**：矛盾时取高置信度者或触发人工。规则引擎关键词本质是启发式，与 LLM 平权会拉低整体准确率。
- **规则为主 + LLM 补充**（如危险品识别场景）：只适合规则能穷举的领域，障碍诊断规则覆盖率不足。
- **纯 LLM**：准确率最高但无离线兜底、成本更高，且失去规则结果的可解释佐证。

## 后果

- 分类以 LLM 为准；规则引擎与 LLM 一致时取较高置信度（规则命中是高精确信号，不因 LLM 低置信被拖低），矛盾时保留双候选并标记 `needs_review` 供教师复核，而非静默丢弃规则结论。
- 迷思概念仅 LLM 产出（规则关键词只覆盖障碍类型），LLM 失败降级时迷思概念维度为空。
- 规则引擎「上下文喂入 + 兜底」本分支实现，「矛盾校验」由融合引擎以「双候选 + needs_review 复核」承接，完整教师审核 UI 归前端分支。
- 规则基采用 JSON 配置驱动（非 YAML），接线由单测守护，防重复 `chemistry_audit/rules/*.json` 的死代码先例。
