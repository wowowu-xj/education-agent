## Purpose

从学生错误作答中诊断学习障碍，输出「障碍类型（怎么错）」与「迷思概念类别（错在哪）」两个正交维度，并聚合为学生与班级画像，支持教师覆盖与阈值自定义。

## ADDED Requirements

### Requirement: 作答记录存储

系统 SHALL 为每次作答持久化一条 `StudentAnswer` 记录，记录作答是否正确（`is_correct`）、学生作答内容、关联题目/考试/班级，以及诊断结果字段（障碍类型、迷思概念类别、置信度）。

#### Scenario: 记录一次错误作答

- **WHEN** 系统接收到一条学生作答（含作答内容、题目、考试、班级）
- **THEN** 系统创建一条 `StudentAnswer` 记录，`is_correct` 标记为错误，诊断相关字段（障碍类型/迷思概念/置信度）初始为空（NULL）

#### Scenario: 诊断字段初始为空

- **WHEN** 一条作答记录尚未经过诊断
- **THEN** 该记录的 `barrier_type`、`misconception_category`、`confidence` 均为空（NULL）

### Requirement: 障碍类型三分类

系统 SHALL 将学生错误归因为三种障碍类型之一：概念理解型（concept）、审题障碍型（reading）、表述障碍型（expression）。

#### Scenario: 分类取值合法

- **WHEN** 系统为一条错误作答判定障碍类型
- **THEN** 判定结果必须是 concept / reading / expression 三者之一，非法取值被拒绝

### Requirement: 迷思概念六分类

系统 SHALL 将学生错误归因到六类迷思概念之一：化学平衡、氧化还原、摩尔计算、有机化学、化学用语、物构知识。

#### Scenario: 迷思概念取值合法

- **WHEN** 系统为一条错误作答判定迷思概念类别
- **THEN** 判定结果必须是六个合法类别之一，非法取值被拒绝

### Requirement: LLM 批量诊断

系统 SHALL 提供批量诊断端点，对一次考试中未诊断的错误作答调用 LLM，单次诊断输出障碍类型、迷思概念类别、置信度、判定依据、干预建议五个字段。

#### Scenario: 批量诊断未诊断作答

- **WHEN** 教师触发一次考试的批量诊断
- **THEN** 系统筛选该考试中最多 10 条未诊断（`barrier_type` 为 NULL）的错误作答，并发调用 LLM 逐条诊断，并将双维度结果与置信度写回各作答记录

#### Scenario: 无未诊断作答

- **WHEN** 触发批量诊断时不存在未诊断的错误作答
- **THEN** 系统返回成功但 `analyzed_count` 为 0，不产生 LLM 调用

#### Scenario: LLM 返回非法分类

- **WHEN** LLM 返回的障碍类型或迷思概念不在合法取值集合内
- **THEN** 系统丢弃该条 LLM 结果，降级为规则引擎兜底分类（迷思概念维度为空），并将该条计入 `failed_count`（表示 LLM 失败已由规则兜底处理）

### Requirement: 置信度融合引擎

系统 SHALL 提供置信度融合引擎，将规则引擎与 LLM 的诊断结果按「规则命中状态 × LLM 置信度」二维决策表融合为最终障碍类型与置信度：双路一致取高置信、冲突时展示双候选并标记人工复核、双低时标记复核、LLM 失败由规则兜底。

#### Scenario: 双路一致取高置信

- **WHEN** 规则引擎命中某障碍类型且 LLM 判定同一类型
- **THEN** 系统以该类型为最终结果，融合置信度取规则与 LLM 置信度的较高者（规则命中为高精确信号，不因 LLM 低置信被拖低）

#### Scenario: 规则与 LLM 冲突展示双候选

- **WHEN** 规则引擎命中的障碍类型与 LLM 结论不一致
- **THEN** 系统以 LLM 分类为默认结果，同时保留规则候选并标记 `needs_review=true` 供教师复核，不静默丢弃规则结论

#### Scenario: 双低标记复核

- **WHEN** 规则引擎未命中（uncertain）且 LLM 置信度低于 0.7
- **THEN** 系统不自动采纳，标记「建议人工复核」，融合置信度取 LLM 值

#### Scenario: LLM 失败规则兜底

- **WHEN** LLM 调用失败或返回非法结果
- **THEN** 系统采用规则引擎分类作为最终障碍类型，置信度为规则引擎的保守值（0.5–0.7），并标记「规则兜底」；迷思概念维度为空

### Requirement: 三级置信度分级

系统 SHALL 依据置信度对诊断结果分级处理：置信度 ≥ 0.8 自动采纳、0.7–0.8 采纳并标记需关注、< 0.7 标记建议人工复核。置信度 SHALL 持久化到作答记录。

#### Scenario: 高置信度自动采纳

- **WHEN** LLM 诊断返回置信度 ≥ 0.8
- **THEN** 系统直接采纳结果并写入作答记录，无需人工介入

#### Scenario: 低置信度标记人工复核

- **WHEN** LLM 诊断返回置信度 < 0.7
- **THEN** 系统写入结果但标记为「建议人工复核」，供教师覆盖入口展示

#### Scenario: 置信度持久化

- **WHEN** 一条作答记录完成诊断
- **THEN** 该记录的 `confidence` 字段保存本次诊断的置信度分数，可被追溯

### Requirement: 学生画像聚合

系统 SHALL 从学生的已诊断作答聚合出障碍类型分布（`barrier_profile`）与迷思概念分布（`misconception_profile`），两者均补齐三种/六种类型，缺失类型为 0。

#### Scenario: 聚合障碍画像

- **WHEN** 一名学生存在多条已诊断错误作答
- **THEN** 系统按各障碍类型计数归一化，写入 `barrier_profile`（concept/reading/expression 三键，和为 1.0），并更新画像时间戳

#### Scenario: 补齐缺失类型

- **WHEN** 学生的已诊断作答未覆盖全部类型
- **THEN** 聚合结果 JSON 仍包含全部键，缺失类型的值为 0.0

#### Scenario: 无诊断数据

- **WHEN** 学生没有任何已诊断作答
- **THEN** 系统返回「暂无足够数据」，不生成画像

### Requirement: 教师覆盖机制

系统 SHALL 允许教师手动覆盖学生的障碍画像，覆盖操作记录操作日志，支持回溯。

#### Scenario: 覆盖学生画像

- **WHEN** 教师以指定障碍类型和原因覆盖一名学生
- **THEN** 系统校验类型合法，保存旧画像，写入新画像（指定类型占 90%，其余各占 5%），并记录操作日志（动作 + 新旧画像 + 原因）

#### Scenario: 覆盖类型非法

- **WHEN** 教师指定的障碍类型不在合法取值集合内
- **THEN** 系统拒绝覆盖并返回错误，不修改画像

### Requirement: 教师阈值配置

系统 SHALL 允许教师为自己的班级配置障碍诊断触发阈值，无历史配置时返回默认值，配置通过 upsert 持久化。

#### Scenario: 获取默认配置

- **WHEN** 教师首次获取诊断配置且无历史记录
- **THEN** 系统返回默认阈值（concept=3、reading=2、expression=3、mastery=3、auto_sync=false）

#### Scenario: 更新配置

- **WHEN** 教师提交新的诊断配置
- **THEN** 系统创建或更新（upsert）该教师的配置并持久化

### Requirement: 班级与知识点聚合查询

系统 SHALL 提供班级障碍分布、知识点维度障碍分析、学生诊断历史三个查询端点。

#### Scenario: 班级障碍分布

- **WHEN** 教师查询某班级某次考试的障碍分布
- **THEN** 系统返回每个学生的主导障碍类型、班级三种障碍类型的人数统计，以及学生薄弱知识点列表

#### Scenario: 知识点维度分析

- **WHEN** 教师查询某班级某知识点的障碍分布
- **THEN** 系统统计该知识点题目集合的错误率与障碍分布，返回各障碍类型人数

#### Scenario: 学生诊断历史

- **WHEN** 教师查询一名学生的诊断历史
- **THEN** 系统按考试分组返回该生每次考试/练习的准确率与障碍分布变化趋势

### Requirement: LLM 多 Provider 回退

系统 SHALL 在调用 LLM 时支持多 Provider 三级回退（MiMo-V2.5 → 通义千问 qwen-turbo → DeepSeek-V4-Flash），每级重试 3 次并指数退避；全部失败时降级为规则引擎兜底分类。

#### Scenario: 首选 Provider 失败回退

- **WHEN** 首选 Provider 调用失败
- **THEN** 系统按顺序尝试下一级 Provider，每级最多重试 3 次并指数退避

#### Scenario: 全部 Provider 失败降级

- **WHEN** 所有 Provider 均调用失败
- **THEN** 系统降级为基于关键词的规则引擎分类，仍返回障碍类型判定

### Requirement: 规则引擎关键词预分类

系统 SHALL 提供基于关键词的规则引擎，对作答进行低成本预分类，产出保守置信度，并承担「上下文喂入 LLM」与「LLM 失败兜底」两个角色。

#### Scenario: 关键词命中预分类

- **WHEN** 学生作答命中某类障碍的关键词（如「分不清」「审题」「写错」）
- **THEN** 系统预分类为对应障碍类型并给出 0.5–0.7 的保守置信度

#### Scenario: 规则结果作为 LLM 上下文

- **WHEN** 规则引擎完成预分类
- **THEN** 系统将预分类结果（含保守置信度）作为额外上下文传入 LLM 诊断
